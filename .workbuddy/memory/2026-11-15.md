## 第三轮：按建议顺序动手修（源码已修改）

用户指令「按照你建议的顺序动手修」。改动 16 个文件，+304/−70（后续又修两处废弃 API 调用）。

### 1. 统一 sendFileData(nullptr,0) 内容复位
- 5 个插件的 `mainwindow.h/.cpp` 各加 public `clearContent()`；
  5 个 `plugin*.cpp` 的 `sendFileData` 在 `(nullptr,0)` 时调它而非直接 return。
- Media 的 `clearContent()` 调 `stopPlayback()`（停解码+音频）再清 videoLabel/进度条/时间标签；
  Pdf 关文档+释放 QBuffer+清 pixmap 与页码框；Book 顺带清 `m_bookData`/`m_sourceName`/书名并显示提示。
- 依据：主程序 `FileWrapper/mainwindow.cpp:630` 在读失败/0 字节时确实送 `(nullptr,0)`。

### 2. PluginMedia 析构 / 超时释放
- `stopWorkerAndWait()` 改为返回 bool；`waitForDecodingStopped()` 加 predicate 循环（防虚假唤醒）。
- `clearFFmpegResources(bool force=false)`：等待超时则**不释放** FFmpeg 上下文，
  置 `m_bCleanupPending` 并停 timer/音频，由 `onDecodingFinished()` 在 worker 退出后补做清理；
  该检查放在 genId 过滤之前。`showVideo` 开头若 pending 则拒绝打开新文件，避免覆盖悬垂指针。
- 析构：先等 worker 退出（3s），卡住则跳过资源释放与 `delete worker`（宁可泄漏不 UAF），
  正常路径 `quit()+wait(3000)` 后显式 `delete m_videoWorker`（它无 parent，此前全程泄漏）。
- `on_stopBtn_clicked` / `doSeek` 两处 `stopWorkerAndWait` 也检查返回值，超时则不碰 FFmpeg 上下文。
- `:1352` `avio_size(m_avioCtx)` → `avio_size(pFormatCtx->pb)`（byPath 通道 m_avioCtx 为 nullptr）。

### 3. PluginBook ZIP 解压上限
- `zipreader.cpp`：读 general purpose flag，加密条目(bit0)不收录；
  `QByteArray(...)` 长度改 `qsizetype`；`inflate()` 用 qsizetype 容量 + 单条目 64 MiB 上限 +
  `uInt` 范围检查 + `cap` 放大时 clamp，消除 quint32→int 截断与 ZIP bomb。
- `mainwindow.cpp loadEpub`：条目数 4096 / 解压后总量 256 MiB 上限，超限 return false。

### 4. PluginPdf 失败复位
- `showPdf` / `showPdfFile` 开头统一 `clearContent()`，加载失败用 `error()`+`pageCount()<=0` 判定；
  `getLineEditPageNum()` 的 `toInt()` 加 ok 校验；缩放上下界改为 `>=300` / `<=20`（原为 305%/15%）。
- 注释里「Qt 6.9 实测」改为本机实测的 6.8.3，并说明该 load 重载返回 void。

### 5. PluginText / PluginPicture
- Text：`isStrictUtf8` 的 `n`/`i` 与 UTF-16BE 交换循环 `k` 改 `qsizetype`；
  `setText` → `setPlainText`；恒 false 的死代码换成真实的 64 MiB 显示上限。
- Picture：`qsizetype::max()` 死代码换成 `uint::max()` 真实判断，`static_cast<uint>`，
  修正错误注释；`applyTransform()` 加 64M 像素总上限（8x 放大不再一次分配数 GB）。
- 两处 `QString::fromUtf16(ushort*)` → `char16_t*`，消掉 Qt6 废弃警告。
