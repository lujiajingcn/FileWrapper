# 修复：PluginMedia 视频画面不跟随界面缩放

## 现象（用户截图）
PluginMedia 插件播放视频后调整主界面大小，画面区里的视频画面**不跟随界面调整**：
窗口已经很大，画面仍停在打开文件时的小尺寸，四周大片黑边。

截图实测（2473x1442 像素图，密度分析定位画面块）：
- 视频画面像素块 x=1409..1857、y=576..880（约 449x305 px）
- 画面区（黑底）却横跨 x=817..2452 —— 画面只占画面区很小一块
- 源视频 `WYHF7168.MP4` = 908x720（宽高比 1.261）

## 根因（三个问题叠加）
1. **输出尺寸在打开文件时被冻结**：`showVideo()` 里算一次
   `outW/outH = computeAspectRatioSize(源宽高, videoLabel 当前尺寸)`，
   建成 `sws_getContext(src, outW, outH, RGB32)` 后，
   解码线程把**每一帧**都缩放到这个固定尺寸（`sws_scale` + `QImage(outW,outH)`）。
   之后 `outW/outH` 再没变过。
2. **`resizeEvent()` 什么也没做，还把状态写坏了**：它只把
   `videoW/videoH = videoLabel->size()`，既没重建 sws 上下文，也没通知解码线程；
   而 `videoW/videoH` 正是 `rebuildSwsContext()` 判断「上下文尺寸是否匹配」的缓存，
   被 resizeEvent 覆写成「控件尺寸」后，这个缓存彻底失真。
3. **`QLabel` 没开 `scaledContents`**：pixmap 按原始像素尺寸居中显示，
   控件变大而画面不变（所以是「一小块画面 + 大片黑边」，而不是拉伸变形）。

叠加后果：插件控件在**还没被布局到最终尺寸**时文件就被打开了，
输出尺寸按那个偏小的尺寸算死 → 之后界面怎么变，画面都不动。

## 修复（Plugins/PluginMedia/mainwindow.cpp + .h）

### A. 缩放上下文与输出缓冲改由**解码线程自己拥有**
原来 `SwsContext` / RGB 输出缓冲 / `AVFrame *pFrameRGB` 归主线程，
但「换输出尺寸」必须释放旧缓冲再重建 —— 主线程释放时解码线程可能正在
`sws_scale`，会 use-after-free。因此把所有权整体搬进 `VideoWorker`：
- `VideoWorker` 新增 `m_sws`、`m_outBuf`、`m_outData[]`、`m_outLinesize[]`
- 新增 `rebuildVideoSws(srcW,srcH,srcPixFmt,newW,newH)`（只在解码线程里调用）
- 新增 `releaseVideoResources()`（只能在解码线程已停止后调用）
- 主线程侧删除 `img_convert_ctx` / `out_buffer` / `out_buffer_size` / `pFrameRGB`
  与 `MainWindow::rebuildSwsContext()`
- `setContexts()` 签名改为传 `AVPixelFormat srcPixFmt`，不再传 sws/缓冲/frameRGB

### B. 尺寸请求走原子量
- 主线程：`requestOutputSize(w,h)` → 把宽高打包进
  `std::atomic<quint64> m_reqOutSize`（`h<<32 | w`），
  **打包是为了保证成对读到**，不会出现「新宽 + 旧高」。
- 解码线程：每帧前读一次，请求值与当前 `outW/outH` 不同才重建。

### C. 窗口缩放 → 更新输出尺寸
- `MainWindow::resizeEvent()`：**先调用基类** `QMainWindow::resizeEvent(e)`
  （原实现漏调，工具栏/停靠窗口不会重新布局），
  再用 `QTimer::singleShot(0, ...)` 把更新**推迟到事件循环下一轮**：
  resize 到达时布局可能还没按新尺寸算完，且拖动窗口的连续 resize 可合并成一次。
- 新增 `MainWindow::updateVideoOutputSize()`：
  1. `ui->mainLayout->activate()` 强制布局重算（拿到最终的画面区尺寸）；
  2. `computeAspectRatioSize()` 算出新的适配尺寸（保持源宽高比）；
  3. `requestOutputSize()` 通知解码线程；
  4. **立刻把当前画面缩放到新尺寸** —— 暂停/播完（不会再有新帧）时，
     这是唯一的更新途径；播放中会被下一帧覆盖。
- `onFrameDecoded()`：帧尺寸与当前目标不一致时先缩放到目标尺寸再显示，
  避免窗口刚缩放时出现「画面尺寸跳变」。

### D. 诊断接口（测试用）
- `VideoWorker::currentOutW()/currentOutH()`（`outW/outH` 改为 `std::atomic<int>`）
- `MainWindow::decodedOutputSize()`：返回解码线程**实际**使用的输出尺寸。
  用来证明「是重新按新尺寸解码」，而不是「把旧帧在界面侧拉伸」。

## 踩坑
28. `QLayout::activate()` 是 public 的，可以在需要时强制布局重算；
    resize 事件里读到的控件尺寸可能是**旧值**（布局尚未按新尺寸激活）。
29. `QTimer::singleShot(0, ctx, functor)` 在 `QEventDispatcherUNIX` 里
    **先于 posted 事件**处理（`processTimers` 在 `processPostedEvents` 之前），
    所以不能指望「延后一轮」就一定拿到布局更新后的尺寸 —— 必须显式
    `activate()` 布局。
30. 跨线程共享「会变的尺寸」要打包成单个原子量，
    否则会读到「新宽 + 旧高」的中间状态。
31. `AVImage` 的 `av_image_fill_arrays` 用 `align=1` 时 linesize = w*4（紧凑），
    `QImage(data, w, h, Format_RGB32)` 正好按紧凑解释 —— 别改成非紧凑对齐。
32. 插件的 `VideoWorker` 没有 parent，析构时必须自己释放 sws/缓冲；
    且删除 worker 之前要先 `m_videoThread->quit()` + `wait()`。

# 新增 PluginWord：Word 文档显示插件（需求：为工程新增一个插件，支持 word 文档的显示）

## 交付
`Plugins/PluginWord/`（新增，7 个源文件 + .pro + json），并接入：
- `Plugins/Plugins.pro` 的 SUBDIRS
- `FileWrapper/mainwindow.cpp` 的 `choosePlugin()`：新增 `arrWordExts` =
  `docx / docm / dotx / dotm / doc`（大小写不敏感），放在 Pdf 与 Book 分支之间。

技术路线：**不引入任何第三方库**，只用 Qt 自带能力 + zlib。
- `zipreader.*`：自包含最小 ZIP 读取器（与 PluginBook 同一份实现，各插件自持一份，
  保持插件独立可编译）；链接 MinGW 自带静态 `libz.a`。
- `worddocument.*`：OOXML → Qt 富文本 HTML 的转换器（核心，约 1400 行）。
  - 用 `QDomDocument::setContent(bytes)`（**默认不开启命名空间处理**，tagName 保留
    `w:p`/`a:blip` 前缀，直接按前缀判断，省掉 URI 映射表）。
  - 解析 `_rels/.rels`（找主文档部件）→ `word/document.xml`；
    `word/_rels/document.xml.rels`（rId → 图片/超链接）、`word/styles.xml`
    （docDefaults 字号、样式 basedOn 链）、`word/numbering.xml`、`docProps/core.xml`。
  - 输出 HTML 子集：`<p>`+少量 CSS、`<b>/<i>/<u>/<s>/<sup>/<sub>`（开关型格式用标签
    而不是 CSS，嵌套不会互相覆盖）、`<table border cellspacing cellpadding>`、
    `<img>`、`<a>`。
  - 表格：先按行收集单元格算网格列位置（gridSpan 累加），**再用「每列当前打开的
    vMerge 起始单元格」把续行折算成 rowspan**，最后跳过被覆盖的续单元格输出。
  - 编号：按 numId/ilvl 维护计数器，`%1..%9` 按 OOXML 语义替换（**`%k` 是绝对层级：
    `%1` 永远是 0 级计数器**，不是「上一级」），支持 chineseCounting（中文数字）、
    roman/letter/decimalZero/bullet；编号以文本前缀 + 悬挂缩进输出。
  - 图片：解析 `wp:extent`（EMU/9525=px）或 VML `style="width:.."`，解码后挂到
    `QTextDocument::setResourceProvider`（**不用 addResource**：setHtml 会清掉
    document 级 resources，provider 与 setHtml 的先后无关，也不会被清）；URL 带
    「每文件递增的代次前缀」，避免同一 tab 里上一份文档的图片缓存串味。
  - 缩放：缓存 DOM，按 `fontScale` 重新 render（所有字号都显式写进 HTML，缩放结果
    可预期），并保留滚动条比例；Ctrl+滚轮也接。
- `mainwindow.*`：QTextBrowser + 工具栏（缩小/放大/实际大小）+ 状态栏（缩放比、
  段数、标题数、表格数、图片数、字数）；代理层 `sendFileData(nullptr,0)` 走
  clearContent + 明确提示（对齐既有插件约定）。

## 关键坑：Qt 6.9.3 富文本对 `margin-*` / `text-indent` **只认 px，不认 pt**
实测（当时的临时探针；现由 tests/ 里的 B19/C13 断言长期覆盖该项行为）：
```
margin-left:18pt  -> QTextBlockFormat::leftMargin() = 0   （静默忽略）
margin-left:36px  -> 36                                    （生效）
text-indent:18pt  -> 0        text-indent:-24px -> -24     （px 生效，负值也行）
margin-top/bottom:12px -> 12
-qt-block-indent:1 -> indent=1（Qt 私有属性，另一套）
margin-left 加在 <div> 上不会传给内部 <p>
```
所以缩进/段间距统一按 `px = pt * 96/72` 输出；`font-size` 用 pt 是正常的（18pt 实测生效）。
首轮测试正是靠这条断言（B19/C13 FAIL）发现的，改 px 后全绿。

# 插件基建 C1+B1：后缀自描述 + API 版本协商

## C1：后缀表从主程序搬进插件
- 删掉主程序 `choosePlugin()` 里的 6 张表 / 90 个后缀，改为三级路由：
  用户映射（QSettings） → `PluginManager::pluginForExtension()` → 内置兜底。
- 每个插件 JSON 增加 `"extensions"`（共 90 项）与 `"apiVersion": 2`；
  可选 `"extensionPriority"`（默认 0，大者优先）。
- **必然的冲突**：`.ts` 既是 MPEG-TS 视频又是 TypeScript 文本。旧代码靠
  choosePlugin 里的判断顺序（文本先于媒体）得到"文本优先"；改成注册表后顺序取决于
  插件加载顺序（文件名排序），会变成 Media 优先。所以给 PluginText 加
  `"extensionPriority": 10` 保持历史行为，并在注册冲突时打告警。
- 新增 sidecar：构建时把 `pluginX.json` 复制成 `plugins/<DLL基名>.json`。
  作用：DLL 加载失败时主程序仍知道它声明了哪些后缀，从而给出
  「插件不可用 + 缺哪个依赖」而不是「未找到插件」。
- 新增公共构建片段 `Plugins/plugin_common.pri`：统一 DESTDIR + sidecar 复制 +
  JSON 依赖（见踩坑 41）。6 个插件的 .pro 都只留 3 行配置。
- `DlgPluginMap::availablePluginNames()` 改用 `PluginManager::knownPluginIds()`，
  加载失败的插件也能出现在「插件映射」下拉框里。

## B1：API 版本协商
- `plugininterface.h` 定义 `PLUGIN_API_VERSION 2`，新增纯虚 `apiVersion()`。
  规则：**接口虚函数表一变就必须 +1**，并同步所有插件 JSON 的 `"apiVersion"`。
- 加载流程 `PluginManager::tryLoadPlugin()`：
  读元数据 → `apiVersionAcceptable()` 校验 → `instance()` → `qobject_cast` →
  `iface->apiVersion()` 复核 → 登记。版本不符的插件**在实例化之前**就被拒，
  避免跨版本调用虚函数（UB）。
- 已创建对象但被拒的情况（接口不符 / 自查版本不符）：loader 存入
  `m_listRejectedLoaders` 保留，**不能卸载 DLL**（否则对象虚表悬空）。
- `BuiltinViewer` 同样实现 PluginInterface，也要补 `apiVersion()`。

## 验证
- 测试套件 119 项全 PASS，新增：
  W2/W3（docx→Word、pdf→Pdf、epub→Book 均由插件 JSON 声明）、
  W4（90 项声明接管，唯一路由 89 + 测试用的 zzz）、

  W8a-d（版本门禁纯函数：当前版本接受 / 无 apiVersion 拒绝 / 版本不同拒绝并回报实际值 / 空元数据拒绝）、
  W9a-b（加载失败的插件仍能把 .zzz 路由到它 → 走「插件不可用」诊断）。
- 干净部署（PATH 无 Qt）：6/6 加载，日志显示 `api= 2 exts= 7/30/1/10/37/5`；
  删掉 Qt6Xml.dll → 4/6（Book+Word），与预期一致。
- **实证「加格式只改插件」**：临时给 PluginText.json 加 `"textile"`，只重编该插件
  （主程序一行未动）→ 探针显示 `textile -> PluginText.dll (routed)`，注册数 89→90；
  还原后又变回 89。

## 踩坑
41. `Q_PLUGIN_METADATA(FILE ...)` 的内容由 **moc** 内嵌，qmake 不会把该 JSON 当依赖：
    只改 JSON 时 `make` 认为无事可做，DLL 与 sidecar 都留着旧元数据（排查极费解）。
    解决：`plugin_common.pri` 里加戳文件 + `PRE_TARGETDEPS`，JSON 比戳新时先用
    `copy /b "头文件"+,, "头文件"` 触碰插件类头（触发 moc 重跑），再更新戳文件。
42. make 的 recipe 由 cmd 执行：不要把 PowerShell 管道写成 `^|` —— 双引号参数里的
    `^` 会原样传给 PowerShell 导致语法错误。要么纯 cmd（copy/echo），要么不转义。
43. 生成 sidecar 的 .pri 里 `$$PWD` 指向 **.pri 自己** 所在目录，不是包含它的插件目录；
    调用方必须写 `PLUGIN_METADATA_JSON = $$PWD/pluginX.json`（完整路径）。
44. 测试里「未知后缀」用例会与 sidecar 兜底用例互斥：未知后缀必须选一个没人声明的
    （例如 `.qzx`），否则新逻辑会把它路由到那个加载失败的插件上。

# C2：统一数据通道 PluginFile + sendFile（接口版本 3）

## 问题
旧通道 `sendFileData(char*, qint64)` 只有"一整块可写内存"：
- 主程序先把条目读成 `new char[]`，插件再复制成自己的 QByteArray —— 每次两份；
- 大文件只能靠"128 MB 阈值 + 临时文件 + 另一套 prefersFileByPath/sendFileByPath"绕开；
- 想真正流式读取（不整块入内存）没有接口可表达。

## 改动
- `include/plugininterface.h`：
  - 新增 **`PluginFile`**（头文件内联，无导出符号）：`fromMemory` / `fromPath`，
    提供 `isMemory()/isPath()/memory()/path()/size()/readAll()/displayName()`。
  - 新增 **`virtual bool sendFile(const PluginFile &)`**，默认实现保持旧插件行为：
    路径 + `prefersFileByPath()` → `sendFileByPath()`；其它读出字节 → `sendFileData()`。
  - **`PLUGIN_API_VERSION` 2 → 3**；6 个插件 JSON 的 `apiVersion` 同步为 3。
- `FileManager::entryContent()`：直接读进 QByteArray（不再经 new char[]/delete[]），
  校验语义与 `QGetFileContent()` 一致（大小/完整性/v2 CRC）；`QGetFileContent` 保留给旧调用方。
- `MainWindow::renderFile()`：
  - 大文件 + 插件支持路径 → `sendFile(PluginFile::fromPath(temp))`；
  - 其余 → `entryContent` 读进 QByteArray → `sendFile(PluginFile::fromMemory(std::move(data)))`；
  - 插件拒绝路径时仍回退内存通道（原行为）。
- **迁移 PluginWord（示范零拷贝）**：新增 `showWord(const QByteArray&)`，
  `PluginWord::sendFile()` 直接把 `file.memory()` 交过去，省掉旧通道的一次完整复制；
  旧 `showWord(char*)` 保留为转调（兼容）。
- Text / Picture / Book / Media / Pdf 暂不迁移，走默认实现 —— 行为与旧版一致
  （仍复制一次），后续可按同样模式逐个迁移，不需要再改接口。

## 验证
- 测试套件 **125 → 133 项**（新增 Y 组）：Y1 内存形态、Y2a/Y2b 路径形态、
  Y3a/Y3b 老插件经默认实现照常收数据（含路径回退）、Y4 路径型插件收到原路径、
  Y5a/Y5b 迁移后的 PluginWord 经 `PluginFile` 渲染出内容。
- 真实程序：6/6 加载，日志 `api= 3`（说明所有插件与主程序版本一致）；
  渲染链路（A 组）经新通道跑通。
- 构建 0 error 0 warning。

## 备注
- 这次升版正好演示了 B1 的价值：如果只换主程序不重编插件，旧 DLL 会在**实例化前**
  被 `apiVersion` 门禁拒绝，而不是运行期崩溃。
- 迁移清单（机械工作，无接口变更）：PluginText/PluginPicture/PluginBook 的
  `sendFileData(char*)` + 局部 `QByteArray` 可换成 `sendFile` + `const QByteArray&`；
  Media/Pdf 主要走路径通道，收益较小。

# 合并时展开"已合并的 .dat"（C11）

## 需求
用户在合并文件时如果选中了已经合并过的 `.dat`，希望把它**拆开**再与其他文件合并，
而不是当成一个普通文件塞进去（否则会变成"归档套归档"，还得再拆一层）。

## 做法（`FileManager::QMergeFiles`）
1. 收集输入时先探测首 4 字节：是 `FWDA` 魔数就走 `inspectArchive()` 读索引，
   把每个条目展开成独立输入（`MergeSource`：源文件 + 内容偏移 + 长度 +
   归档内相对路径），而不是一个普通文件；损坏的归档明确报错，不静默当普通文件。
2. 路径规则：普通文件仍按"绝对路径相对公共根"生成；归档条目直接沿用**归档内
   相对路径**。因此 `writeV2Header()` 新增可选参数 `pStoredPaths`：
   给了就按给定路径写，不给保持原来的相对路径计算（保存/另存为路径不受影响）。
3. 撞名处理：展开后很容易重复（归档里已有 `photo.png`，又选中了 `photo.png`），
   自动在扩展名前加 ` (2)`、` (3)`…，大小写不敏感比较。
4. 内容复制：`streamCopy(src, offset, len, ...)` 从归档里的原偏移读取，
   不再假设内容从 0 开始；CRC 按复制结果重新计算并写入 v2 头部。
5. UI：合并进度框在检测到归档输入时显示"其中 N 个是已合并归档，将先拆分再合并"；
   成功消息追加"其中 N 个条目来自 M 个已合并归档（已先拆分再合并，不是嵌套归档）"。

## 验证
- 新增 G 组 3 项：普通合并得到 2 条目归档 → 归档 + 普通文件再合并得到 3 条目
  且没有 `.dat` 嵌套 → 撞名自动改名为 `pic (2).png`。
- 测试 **171 项全 PASS**（`-SkipShots` 168）；真实程序 8/8 插件加载。
- 边界：只展开一层（归档条目本身若又是 `.dat` 就作为普通条目保留）；
  空归档输入会被忽略，全部为空时给出"没有可合并的内容"。

# P0 修复：关闭确认 + 保存路径规划（C14）

## 关闭窗口确认
`MainWindow::closeEvent` 调用 `confirmDiscardOrSaveIfDirty()`（保存/放弃/取消），
取消则 ignore；确认后 `closeAllTabs()` 释放插件实例再退出。
实测：脏归档 Alt+F4 弹出「未保存的改动 / Save / Cancel / Discard」，点 Cancel 程序保持打开。

## 保存路径规划
`rewriteArchive()` 原来用 `commonRoot(allPaths)` + `writeV2Header` 的
`makeRelative(path, root)`：跨盘时 root 为空，`makeRelative` 退化为文件名，
导致**所有条目的目录结构被拍平**，不同目录的同名文件变成**重复路径**（实测 3 条 same_name.bin）。
现新增 `FileManager::computeStoredPaths()`：
- 有公共根：root=公共根、条目存相对路径；
- 跨盘/无公共根：root 为空、盘符当首段（`E:/x` → `E/x`），保留来源目录；
- 写盘前检查重复 relPath，重复则 `save()` 失败并提示「归档内出现重复路径…」。
`rewriteArchive` 的磁盘空间预检也改为按实际存储路径精确计算头部大小。

实测（GUI 完整链路）：跨盘归档 + 添加 D: 文件 → 保存后 `root=''`，条目
`E/fw_qa/dup/in/other.txt`、`D/fw_qa_extra/cross_drive_test.txt`，无重复。
