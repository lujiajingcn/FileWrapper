## 踩坑记录（下次直接照抄）
1. **Qt 平台插件必须部署**：测试 exe 所在目录要有 `plugins/platforms/qoffscreen.dll`，
   否则 `QApplication` 构造静默卡死（表现为"程序无输出直到超时"）。
2. **MinGW 运行时 DLL 必须在 exe 同目录或 PATH**：`libgcc_s_seh-1.dll`/`libstdc++-6.dll`/
   `libwinpthread-1.dll`，缺了进程静默失败（EXIT=127）。
3. **不要用 `QPluginLoader::instance()` 长期持有插件实例**：进程退出时 DLL 被卸载
   而内部 QWidget 仍存活 → vtable 悬空 → 段错误。必须用主程序同样的
   `createInstance()` + `delete` + `unload()` 顺序。
4. **qmake/Makefile 时间戳陷阱**：在同一 shadow 目录反复 `qmake` 不同 .pro 会让
   `Makefile.Release` 规则与源文件脱节，`make` 报 "Nothing to be done" 但实际没编译。
   → 改完源码要 `rm -f Makefile Makefile.Release Makefile.Debug` 再 `qmake`。
   **更坑**：`make` 报成功但 exe 是旧的，导致"测试了旧二进制"而误判。
5. **Git Bash 下 `taskkill /F` 会被当成路径** → 用 `MSYS_NO_PATHCONV=1 taskkill.exe -F -IM x.exe`。
6. **输出缓冲**：管道 `| tee` 会缓冲，进程被杀则日志全丢 → 改用 `> file 2> file`，
   或在 C++ 里用 `fprintf(stderr,...) + fflush(stderr)`。

# 2026-11-16 合并失败「条目内容区重叠」—— 0 字节文件导致的假阳性

## 用户报告
合并 `E:\testfiles_copy` 报错：
`[FileManager] "文件合并失败：临时归档校验失败：条目内容区重叠（第 635 条与前一区间冲突）"`

## 根因（已完整确证，非猜测）
1. **写入端** `writeV2Header`（`filemanager.cpp:513`）按文件长度累加内容偏移：
   `cp += infos.at(i).nFileLen`。**0 字节文件不推进游标**，于是「它自己」和
   「它后面那条」共享同一个 `contentPos`。这在语义上**正确**（0 字节文件不占内容区）。
2. **解析端** `parseFromDevice`（`filemanager.cpp:233`）的重叠检测把**零长度区间
   `[P,P)` 也纳入判定**。排序后 `[P,P)` 与 `[P,P+N)` 首地址相同，而 `std::sort`
   **不保证稳定** → 两者相对次序未定义：
   - `[P,P)` 排在前 → `P < P` 假 → 不报错
   - `[P,P+N)` 排在前 → `P < P+N` 真 → **误报「内容区重叠」**
3. 因此**是否触发取决于排序结果**，报错位置随目录结构漂移 —— 这正是
   「第 635 条」这种位置不稳定的报错。

## 实测证据
- `E:\testfiles_copy`：9665 文件 / 4.6 GB，其中 **8 个 0 字节文件**
  → Python 独立复算 contentPos 布局：恰好 **8 对相邻条目共享 contentPos**
- 真实 `FileManager` 复现：100 文件、第 63 个为 0 字节 → 报
  `条目内容区重叠（第 64 条与前一区间冲突）`，与用户报错**同构**
- 扫描 224 种 (N, zeroAt) 组合：**22 种触发**，修复后 **fail=0**

## 修复
`FileWrapper/filemanager.cpp` 的重叠检测：**零长度条目不参与重叠判定**
（`if (e.size == 0) continue;`）。零长度条目本就不占内容区，无从重叠；
非零长度区间的真重叠仍被拦截。

## 新增回归用例 `mergezero`（40 断言）
覆盖 12 组**实测确认必然触发**的 (N, zeroAt) 配置 + 真重叠仍被拦截 +

## 新增踩坑（12-16）
12. **沙箱会拦截子进程递归扫描 `E:\testfiles_copy`**：Bash 自身 `ls`/`find`
    正常，但 exe 里用 `QDirIterator`/`QDir::entryInfoList` 递归该目录时进程
    被杀（**RC=127、无任何输出**）。绕过：**由 Bash 预先枚举路径写入清单文件**，
    程序只读清单，不再自己递归。需 `dangerouslyDisableSandbox` 才会真正生效。
13. **`QFile::copy` 在源文件仍被打开时会把内容放大到 1.4 GB**（稀疏/偏移异常），
    别用它做归档改写实验。改为**直接构造字节**（自己算头部 CRC：
    `gh[0..15] + gh[20..23] + 区域[24,hdrSize)`）。
14. **归档里 `contentPos` 必须严格大于 `hdrSize`**（校验用的是 `pos < hdrSize`），
    构造测试归档时容易踩。
15. **`rm -rf` 误删 `release/plugins` 目录本身** → 链接报
    `cannot open output file .../PluginPicture.dll: No such file or directory`，
    看起来像链接器问题。**只删目录里的文件，别删目录**。
16. **回归用例位置要挑对**：0 字节文件放在哪一位会影响 `std::sort` 的相对次序，
    并非任意位置都触发。用例里必须挑**实测确认会触发**的若干配置，
    否则回退修复后用例仍全 PASS（假阴性）。
