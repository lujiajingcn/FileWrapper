# 2026-09-11

## FileWrapper：文件列表改为「按合并前路径层级」树形展示

### 背景
合并归档（`FWDA` 格式）的条目里存的是**绝对路径**；加载后 `populateFilePathView()`
把每个文件当成**单列一行**平铺，`treeView` 完全没用到父子结构。

### 已确认的设计决策（用户选择）
1. **树根基准**：取所有条目的**最长公共父目录**作为根（跨盘符等无公共前缀时不建根，
   直接用盘符/首段作顶层）。不改归档格式，旧的 `.dat` 也能直接按树形展示。
2. **显示模式**：树形为默认，另加「树形显示 / 平铺显示」切换；平铺模式下
   「显示路径 / 显示名称」才可用，树形模式下这两个按钮置灰。
3. **单链压缩**：只有唯一子目录的链条并成一行（`a → b → c` 显示为 `a/b/c`）。

### 改动内容
- `FileWrapper/mainwindow.h`
  - 新增槽 `onActionViewTreeTriggered` / `onActionViewFlatTriggered`
  - 新增 `populateFilePathList(bool)` / `populateFilePathTree()` / `updateViewActionState()`
  - 新增 `collectExpandedItems()` / `restoreExpandedItems()`（重建前后保持展开态）
  - 新增成员 `m_acViewTree` / `m_acViewFlat` / `m_bTreeMode = true`
- `FileWrapper/mainwindow.cpp`
  - 文件顶部新增静态辅助：`isFileLeafItem()`（**文件叶子才带 FILEINFO，目录节点不带**）、
    `normalizePath()`（分隔符归一 + 去尾斜杠）、`commonDirPrefix()`（最长公共目录前缀）、
    `compactSingleChainDirs()`（单链压缩）
  - `populateFilePathView()` 改为按 `m_bTreeMode` 分派；原平铺逻辑移入 `populateFilePathList()`
  - 树形构建：根节点 = 公共父目录，`QMap<相对目录路径, 节点>` 去重复用目录节点，
    叶子 `setData(FILEINFO)`；目录/文件用 `SP_DirIcon` / `SP_FileIcon`
  - **构造函数顺序调整**：`m_fileManager = new FileManager` 提到 `initWidgetFilePath()` 之前
    （`updateViewActionState()` 会查询 `isArchiveLoaded()`，否则空指针）
  - 三处依赖「行号 = 文件」的入口全部改为按叶子判断：
    双击（目录只做展开/折叠）、右键菜单（目录不弹菜单）、删除 / 导出（目录给提示不让操作）
  - `updateViewActionState()` 统一管理四个动作的 `setEnabled`，并加入 `isArchiveLoaded()` 判断

### 本机构建注意（重要，见同名 skill）
`mingw32-make` 用**裸命令名** `g++` 调编译器时会报
`g++: error: CreateProcess: No such file or directory`（找不到 cc1plus）
或链接时 `-fuse-linker-plugin, but liblto_plugin-0.dll not found`。
**原因**：make 传 `argv[0]="g++"`，MinGW 7.3.0 的 GCC 无法据此定位自身安装前缀。
**绕过**：给 make 传绝对路径的编译器变量（编译用 `CXX`/`CC`，链接用 **`LINKER`**，
不是 `LINK`）：
```
mingw32-make "CC=<abs>/gcc.exe" "CXX=<abs>/g++.exe" "LINKER=<abs>/g++.exe" "AR=<abs>/ar.exe" "RANLIB=<abs>/ranlib.exe"
```
QtCreator 内部构建不受影响（它的环境能正常解析）。
